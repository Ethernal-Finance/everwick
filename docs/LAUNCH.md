# Release assessment

**Launch readiness: 38/100 for a public paid launch.** This is an internal engineering assessment, not an independent audit. The local playable loop is present; payment delivery, account lifecycle, hosted operations, economy longevity and product retention are unproven. Do not describe this build as production ready.

| Area | Current evidence | Public launch gate |
|---|---|---|
| Playable core | Movement, 100 NPCs, 12 seeded businesses, ownership, profiles and memories | Observed usability sessions and retention |
| Economy | Integer transfers, inventory conservation, wages, rent, production, bankruptcy and regression tests | Long-horizon stability, exploits and market concentration tests |
| Persistence | SQLite atomic snapshots, offline replay, command replay tests | Backup restore drill and interruption/soak tests |
| Payments | Signed fixture tests, idempotent fulfillment and refund tests | Real Stripe sandbox delivery and live-mode operational review |
| Art | User-supplied Fantasy Dreamland assets integrated, credits retained | Review every animation/collision and package distribution |
| Security | Server authority, CSRF, sessions, admin roles and basic limits | Recovery, verification, MFA, abuse defense and independent review |
| Launch platform | Website, tiers, waitlist, referrals, history and admin | Public host, domain, privacy/terms/contact and email delivery |
| Marketing | Calendar, campaign, press copy and launch checklist | Real clips, validated stories, community and creator relationships |

## Next ten development priorities

1. Observe ten new players completing the first-business loop; fix the three largest points of confusion.
2. Finish NPC pathfinding, building interiors, collision layers, interpolation and distinct visual identities.
3. Run 90-day economy scenarios with shocks, inflation/deflation bounds, hunger, concentration and recovery criteria.
4. Add verified email, account recovery, administrator MFA, consent withdrawal and data export/deletion.
5. Complete real Stripe test Checkout/refund/retry/receipt delivery and reconciliation tests.
6. Deploy on a persistent host with TLS, backups, health alerts and a rehearsed restore procedure.
7. Deepen relationship-driven decisions, proprietor ambitions, dialogue evaluation and story arcs.
8. Deliver actual cosmetic entitlements, founder registry, reserved business names and fulfillment dates.
9. Partition towns, add authoritative multiplayer movement and leased background AI jobs.
10. Prove acquisition-to-return metrics with a closed alpha, then set a public launch date from evidence.

## 90-day roadmap

| Period | Deliverable | Exit criterion |
|---|---|---|
| Days 1–7 | First-session UX, art/collision pass, structured task board | 8/10 fresh testers buy and adjust a business without help |
| Days 8–14 | Economic telemetry, scenario runner, memory evaluation | 30-day baseline remains playable; reproducible failure scenarios |
| Days 15–21 | Email verification, recovery, admin MFA, privacy controls | Account and abuse test matrix passes |
| Days 22–30 | Staging deployment, Stripe sandbox, backups and monitoring | Complete payment/refund/restore rehearsal |
| Days 31–42 | Twenty invited testers, weekly story collection | Repeated return visits; document why players return or leave |
| Days 43–49 | Improved citizen agency and onboarding based on feedback | First-session completion ≥80%; no unresolved currency exploit |
| Days 50–60 | Founder benefits implementation and campaign dry run | Every sold benefit has delivery status and owner |
| Days 61–70 | Controlled 100-player alpha and load testing | Measured request/tick latency within budget, no data loss |
| Days 71–80 | Creator preview, accessible UI pass, support workflows | Support/incident escalation rehearsal complete |
| Days 81–90 | Go/no-go review, trailer and launch candidate | Meet launch checklist; otherwise extend alpha with a public explanation |

Retention targets are hypotheses, not results: first-session business ownership 50%, day-1 return 35%, day-7 return 15%, and at least one meaningful player-visible event per returning session. Instrument and adjust after observing real cohorts; do not manufacture targets as marketing claims.

## Launch checklist

- [ ] Named company/operator, working contact, privacy notice, terms, refund rules and support coverage.
- [ ] Asset purchase records, credited license and no forbidden crypto features.
- [ ] No committed credentials or publicly downloadable raw source assets.
- [ ] Real sandbox payments and receipts; signed webhook retries and refund reconciliation.
- [ ] Every founder benefit either delivered or clearly described with realistic future status.
- [ ] No fake funding, testimonials, player counts or fictional simulation claims.
- [ ] Verified email, consent withdrawal, deletion/export and account recovery.
- [ ] Security review, privilege tests, abuse controls and emergency sales shutdown.
- [ ] TLS deployment, persistent storage, backups, restore drill and health alerts.
- [ ] Accessibility/keyboard/mobile testing and game tutorial with observed players.
- [ ] Long-running economic and persistence tests, useful return briefings and readable Gazette.
- [ ] Creator/press kit, trailer, honest screenshots and community rules.
- [ ] Support owner and on-call owner assigned for launch week.

No launch posts, press pitches, emails or real-money transactions have been sent.
